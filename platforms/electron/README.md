# Desktop host boundary

The renderer is a separate composition entry using the same controller, rule engine, UI, cookie/query adapter and local JSON/SQLite codecs as the browser. There is no Node integration, preload or general filesystem IPC in the renderer. Main-process code owns the fixed resource handler, persistent session, window restrictions and user-initiated download options.

The app-owned origin is https://tetris.invalid/index.html. The persistent session intercepts HTTPS and maps only that exact host and whitelisted packaged paths to local files, with explicit MIME types and CSP. It makes no server, DNS or TLS connection for those resources. This retains the full Secure/SameSite=Lax cookie contract. A real Electron 45.2.1 probe showed that standard/secure custom schemes do not store cookies; [Electron issue 27981](https://github.com/electron/electron/issues/27981) documents the underlying limitation. The supported launch argument uses the same fixed HTTPS origin; remote destinations, credentials, ports and raw traversal are rejected.

Native blur/hide/minimize events dispatch one fixed standard blur event into the shared input/lifecycle handler. That supplements DOM visibility events on headless/occluded windows, releases held input and pauses. No focus/show callback resumes play. The renderer receives no callable native interface.

runtime.json and the upstream SHASUMS256.txt pin Electron 45.2.1. runtime-files.json locks every retained Windows runtime file. Packaging verifies the upstream archive before reading it, omits the default demo app, renames only the launcher and streams all required runtime assets plus the built app into the portable ZIP. Verification checks every runtime hash, executable/DLL x64 PE header, owned resource, schema/Wasm and source/version metadata. All following releases retain the browser and Windows packages.

The opt-in pytest native probe invokes the pinned Node Playwright Electron driver against extracted app resources, isolated profile and temporary downloads. It checks the secure origin, real cookies/default URL writes, reload/reopen continuity, game input, native hide pause/no automatic resume, SQLite download/restore, renderer isolation, denied popup and session-score clearing. It redirects only test download destinations to avoid OS dialog interaction. On this Linux host it uses Ozone headless and a process-local --no-sandbox root-test flag; release source retains sandbox=true and does not add that flag. These compatible-host checks do not claim native Windows launch, taskbar or OS dialog verification.

Primary API references: [Electron protocols and sessions](https://www.electronjs.org/docs/latest/api/protocol), [Electron security](https://www.electronjs.org/docs/latest/tutorial/security) and [Playwright Electron automation](https://playwright.dev/docs/api/class-electron).
